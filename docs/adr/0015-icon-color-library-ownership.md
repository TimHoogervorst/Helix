# Icon and Color Library Ownership Split

The platform's shared Icon Library (Lucide references + uploaded custom SVGs, stored as sanitized markup in the DB) and Color Token palette (admin-managed named colors, one hex each, foreground derived by luminance) are owned by `helix_core` — models and APIs live there, next to `Schema`/`SchemaType` — while the curation UI (a single "Labelling" settings section with Tags / Colours / Icons tabs) is contributed by the tags mod, and the shared `IconBadge`/`IconPickerPopover` components live in the shell's shared components. This three-way split follows the mod system's dependency direction: `Schema` lives in core and must reference icon keys, shell surfaces (column type icons, sidebar) must render the picker without importing from mods, and mods may not be imported by core or shell. The tags mod is the curation *surface*, not the data owner — the same relationship the settings mod has to protocol data.
